รายงานสต๊อกรวมของที่เพิ่งรับเข้าไปแล้ว — ถ้าทำตามแผนเดิม (ตั้งสต็อกตามรายงาน แล้วบวกใบรับเข้าอีก) สินค้า 161 รายการจะเด้งเป็นสองเท่า

ช่องโหว่ข้อมูลที่พบ 2 จุด

1 · ต้นทุนสินค้าเปิดให้ทุกคนอ่าน ปิดแล้ว

RLS คุมได้แค่ระดับแถว ไม่ใช่ระดับคอลัมน์ — แถวสินค้าที่เผยแพร่เปิดให้ทุกคนอ่าน cost_price จึงติดไปด้วย ใครก็ตามที่เปิดเว็บร้านมี anon key อยู่ในมือ ยิง REST ตรง ๆ ก็ได้ต้นทุนทั้งร้าน

บทเรียนที่แพงที่สุดของรอบนี้

คำสั่งถอนสิทธิ์รอบแรก (0069b) รันผ่านโดยไม่มี error แต่ไม่ได้ทำอะไรเลย — Postgres ไม่ยอมถอนทีละคอลัมน์ออกจากสิทธิ์ที่ให้ไว้ทั้งตาราง สิ่งเดียวที่จับได้คือบล็อกตรวจสอบท้ายไฟล์ที่ raise แทนที่จะรายงานว่าสำเร็จ · ต่อจากนี้ migration ที่แตะสิทธิ์ทุกไฟล์จะมีบล็อกตรวจผลเสมอ

2 · ใครก็ยึดตำแหน่ง "เจ้าของร้าน" ทางไลน์ได้ ยังไม่ปิด

แอดไลน์ร้านแล้วพิมพ์คำว่า "เจ้าของร้าน" คนแรก = ได้รับแจ้งเตือนของเจ้าของทั้งหมด · ไม่มีการตรวจสอบใด ๆ · "first come wins" และแย่งคืนไม่ได้

3 · ข้อมูลลูกค้าคนก่อนค้างในเครื่อง แก้แล้ว รอ deploy

ปุ่ม logout ล้างแค่สถานะล็อกอิน — ประวัติออเดอร์ ตะกร้า และที่อยู่ยังค้างอยู่ คนต่อไปที่ล็อกอินบนเครื่องเดียวกันจึงเห็นของคนก่อน · ไม่ใช่ปัญหาฝั่งเซิร์ฟเวอร์ เซิร์ฟเวอร์ให้ข้อมูลถูกคนเสมอ

LINE ทำให้เจอง่ายที่สุดเพราะล็อกอินเสร็จได้ session ใหม่มาเลย ไม่ผ่านหน้า logout — โค้ดเดิมจึงไม่มีจังหวะได้ล้างเลยสักครั้ง · แก้แล้วโดยดักไว้ 3 จุด รวมถึง "user id เปลี่ยนไปจากเดิม"
